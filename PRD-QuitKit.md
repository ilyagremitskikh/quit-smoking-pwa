# PRD — «QuitKit»: приложение для отказа от курения на цитизине

**Версия:** 1.1
**Дата:** 29.05.2026
**Автор:** Ilia
**Статус:** Draft

> ⚠️ Дисклеймер: приложение — вспомогательный трекер, а не медицинский продукт. Схема приёма берётся из бумажной инструкции в упаковке «Никуриллы Цитизин» и сверяется с ней. По вопросам самочувствия — к врачу.

---

## 1. Контекст и проблема

Пользователь начал 25-дневный курс цитизина («Никуриллы Цитизин»). Схема приёма сложная: интервал между таблетками меняется по фазам (от 2 до 5 часов), плюс плавающее время в зависимости от даты старта. Держать это в голове тяжело, а сорваться легко.

Нужен максимально простой инструмент, который:
- считает, **когда принять следующую таблетку**, и даёт отметить приём в один тап;
- считает **дни без сигарет** и позволяет отметить срыв («закурил»);
- показывает **прогресс** по курсу;
- содержит **личное видеопослание** как мотивацию в трудный момент.

**Ключевой принцип продукта: минимум действий от пользователя.** Чем больше нужно заполнять — тем выше шанс, что забросят. Никаких лишних трекеров (вода, сон, подъём и т.п.).

## 2. Цели и не-цели

### Цели
- Довести курс цитизина до 25-го дня с правильной периодичностью приёма.
- Дать видимый, мотивирующий прогресс отказа от курения.
- Удержать мотивацию через персональное видеопослание и ежедневные мотивационные цитаты.
- Остаться полезным **после окончания 25-дневного курса**: жить как постоянный трекер «дней без сигарет» со статистикой и возможностью отметить срыв в любой момент.

### Не-цели (явно вне scope)
- Трекинг воды, сна, времени подъёма/отхода ко сну.
- Мультипользовательский режим, аккаунты, авторизация (приложение для одного человека).
- Публикация в App Store — это PWA «на экран Домой».
- Медицинские рекомендации, расчёт дозировок сверх захардкоженной схемы.

## 3. Целевой пользователь

Один человек (автор). iPhone, приложение добавлено на экран «Домой». Технически грамотный, хостит сам.

## 4. Схема приёма (захардкожена)

Источник — инструкция «Никуриллы Цитизин» (стандартная 25-дневная схема цитизина):

| Фаза | Дни | Интервал между приёмами | Таблеток в день |
|------|-----|------------------------|-----------------|
| 1 | 1–3 | 2 ч | 6 |
| 2 | 4–12 | 2,5 ч | 5 |
| 3 | 13–16 | 3 ч | 4 |
| 4 | 17–20 | 5 ч | 3 |
| 5 | 21–25 | по 1–2 в день | 1–2 |

**Веха:** полный отказ от курения — не позднее 5-го дня курса (подсвечивается в UI).

**Расчёт времени приёмов:** первая таблетка дня — это время первого приёма (задаётся один раз при старте курса, по умолчанию — момент старта). Дальнейшие приёмы дня = первое время + интервал фазы × N, пока не набрано нужное число таблеток за день. Решение без отдельных настроек «подъём/сон»: пользователь один раз указывает удобное время первого приёма.

## 5. Функциональные требования

### 5.1 Старт курса
- При первом запуске пользователь задаёт дату/время старта (по умолчанию — сейчас) и время первого приёма.
- Система генерирует полное расписание на 25 дней.
- Курс можно сбросить/перезапустить (на случай прерывания и повтора через 2–3 мес).

### 5.2 Приём таблеток
- Главный экран показывает: текущий день и фазу курса, время до следующего приёма (обратный отсчёт), крупную кнопку **«Принял ✓»**.
- Тап по кнопке логирует приём (`taken_at = now`) и пересчитывает следующий.
- Лента приёмов на сегодня: сколько выполнено / осталось.
- Пропущенный приём помечается как `skipped`/`late` автоматически по времени.

### 5.3 Учёт курения
- Кнопка **«🚬 Закурил»** — логирует срыв одним тапом (без обязательных полей, без осуждающего текста).
- При нажатии — мягкий перехват: предложение посмотреть видеопослание (см. 5.5).
- Срыв **не обнуляет** весь прогресс жёстко; счётчик «без сигарет» считается от последнего срыва, но история сохраняется (см. 5.4).

### 5.4 Счётчик и прогресс
- Крупный счётчик «Без сигарет: N дней» (от последнего залогированного срыва или от старта).
- Экран «Прогресс»:
  - календарь курса (день зелёный, если все таблетки приняты);
  - график адхеренса (принято/запланировано по дням);
  - график срывов по дням (тренд);
  - вехи: день 5 (отказ), день 25 (финиш).

### 5.5 Видеопослание (пасхалка)
- Заранее загруженное локальное видео — обращение к самому себе «ради чего всё это».
- Доступно: (а) из скрытой/неприметной точки в UI; (б) автоматически предлагается при нажатии «🚬 Закурил».
- Видео хранится на сервере (монтируется томом), отдаётся приложением.

### 5.6 Мотивационные цитаты
- Ежедневно на главном экране показывается мотивационная цитата.
- Источник — захардкоженный/локальный список цитат (без внешних API), ротация по дню.
- Цитата дня детерминирована (одна и та же в течение суток), меняется каждый день.

### 5.7 Жизнь после курса
- После дня 25 курс переходит в статус `done`, но приложение **продолжает работать** как постоянный трекер.
- Главный экран в этом режиме: крупный счётчик «Без сигарет: N дней», кнопка «🚬 Закурил», цитата дня, доступ к статистике и видео.
- Блок графика приёма таблеток скрывается (курс завершён), статистика по курсу остаётся доступной в истории.
- Срыв можно отметить в любой момент и после курса — счётчик пересчитывается.

## 6. Уведомления

### Реалистичная оценка для iOS PWA
Настоящие Web Push на iPhone работают при условиях:
- iOS 16.4+;
- приложение **добавлено на экран «Домой»** (в обычной вкладке Safari push не работает);
- HTTPS (есть через Nginx Proxy Manager);
- Service Worker + подписка через Web Push API с VAPID-ключами;
- серверный планировщик (cron), отправляющий push в нужное время по расписанию.

### План по фазам
- **MVP:** напоминания работают, пока приложение открыто (визуальный таймер + локальное уведомление в активной сессии). Серверного push нет.
- **v1.1:** полноценный Web Push — Service Worker + VAPID + cron-планировщик на бэкенде, шлёт «пора принять таблетку» по расписанию даже при закрытом приложении.

Push в MVP не блокирует запуск: основная ценность (таймер + отметка + прогресс) работает сразу.

## 7. UX/UI принципы

- **Mobile-first**, крупные тач-зоны, минимум текста и полей.
- Один главный экран закрывает 90% сценариев: таймер + «Принял» + счётчик + «Закурил».
- Тёмная тема по умолчанию.
- Тактильный отклик (haptics) при отметке приёма.
- Никаких форм, которые надо заполнять регулярно.

### Структура экранов
1. **Сегодня** (главный): таймер до приёма + кнопка «Принял» (во время курса) ИЛИ только счётчик (после курса), счётчик без сигарет, цитата дня, кнопка «🚬 Закурил».
2. **Прогресс**: календарь + графики + вехи (доступен и во время, и после курса).
3. **Видео**: послание себе.
4. **Настройки** (минимальные): время первого приёма, цена пачки (опц.), вкл/выкл уведомления, сброс/перезапуск курса.

## 8. Модель данных (SQLite)

| Таблица | Поля |
|---------|------|
| `course` | id, start_date, first_dose_time, status (active/done/aborted) |
| `dose_schedule` | id, course_id, day_number, phase, planned_time, interval_minutes |
| `dose_log` | id, schedule_id, taken_at, status (taken/skipped/late) |
| `smoke_log` | id, logged_at, note (nullable) |
| `settings` | id, pack_price (nullable), reminders_enabled |
| `push_subscription` | id, endpoint, p256dh, auth (для v1.1) |
| `quote` | id, text, author (nullable) — список мотивационных цитат |

## 9. Технический стек

- **Frontend:** React + Vite, PWA (manifest + service worker), Tailwind, Recharts для графиков.
- **Backend:** Node.js (Fastify), REST API + раздача статики + (v1.1) cron-планировщик push.
- **БД:** SQLite через better-sqlite3.
- **Push (v1.1):** библиотека web-push (VAPID).
- **Контейнеризация:** один Docker-образ (собранный фронт раздаётся бэкендом).
- **Reverse proxy / SSL:** Nginx Proxy Manager, поддомен `quit.mindhackerdev.ru`.

## 10. CI/CD

1. Push в Git-репозиторий.
2. CI (GitHub/Gitea Actions): lint → build фронта → сборка Docker-образа → push в registry (GHCR или локальный).
3. Деплой на домашний сервер: webhook или Watchtower → `docker compose pull && up -d`.
4. Стек-файл в `/opt/stacks/quitkit/`, управление через Dockge.

## 11. Метрики успеха

- Курс доведён до дня 25.
- Доля принятых вовремя таблеток (адхеренс) — видна в приложении.
- Дни без сигарет растут.
- (Личная) метрика: пользователь реально открывает приложение и тапает, а не забрасывает.

## 13. Решённые вопросы

- **Видео:** монтируется томом (volume) на сервере, не вшивается в образ.
- **Экспорт SQLite:** не требуется.
- **Жизнь приложения:** работает бессрочно, после курса — режим постоянного трекера.
