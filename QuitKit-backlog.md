# QuitKit — бэклог задач

Сформировано по итогам проработки PRD, архитектуры, дизайна и ревью логики.
Формат заголовков: инфинитив + объект, одно действие на тикет. Типы: **Задача**, **Ошибка**, **Техдолг**, **User Story**.
Приоритеты: **P0** (портит данные / опасно), **P1** (честность и корректность), **P2** (ощущение качества), **P3** (приятно иметь).

---

## Эпик 1. Сохранность и необратимость данных (P0)

Это то, на что напорёшься в первый же день использования или что молча испортит статистику.

| # | Тип | Заголовок | Описание / критерии |
|---|-----|-----------|---------------------|
| 1.1 | Задача | Добавить отмену приёма таблетки | После подтверждения «Принял» показывать тост «Отменить» на 5 сек. Тап по уже принятому слоту — откат в «ждёт». Запись в `dose_log` удаляется/инвалидируется. |
| 1.2 | Задача | Добавить отмену записи срыва | После «Покурил» — тост «Отменить» на 5 сек. Откат восстанавливает прежнее значение серии. |
| 1.3 | Задача | Реализовать коррекцию времени приёма задним числом | Дать изменить `taken_at` у записи (принял в 10:15, отметил в 11:00). Влияет на расчёт адхеренса по интервалам. |
| 1.4 | Техдолг | Перенести хранение данных с localStorage на серверный SQLite | Данные курса/доз/срывов должны жить на сервере, не в браузере. iOS может выселить данные PWA; чистка Safari не должна стирать прогресс. |
| 1.5 | Ошибка | Убрать демо-режим из прод-сборки | Кнопки «День 1/5/13/…» перезаписывают реальные данные одним тапом. Вынести под флаг сборки или удалить из прода. |
| 1.6 | Задача | Настроить резервное копирование SQLite | Периодическая копия файла БД с тома + ротация (cron на сервере). Экспорт в самом приложении не нужен. |

## Эпик 2. Корректность бизнес-логики (P1)

Метрики и расчёты, которые сейчас врут или не продуманы.

| # | Тип | Заголовок | Описание / критерии |
|---|-----|-----------|---------------------|
| 2.1 | Ошибка | Исправить расчёт адхеренса на наступившие слоты | Считать принято / (слоты, наступившие к этому моменту), а не / все 150 таблеток курса. Убирает «1%» на дне 1. |
| 2.2 | Задача | Считать «сэкономлено» и «не выкурено» от дня 5 | База отсчёта — день полного отказа, а не старт курса. До дня 5 показывать 0. |
| 2.3 | Задача | Реализовать строгое обнуление серии при срыве | Срыв после дня 5 обнуляет «дней без курения» в 0. История срывов сохраняется. |
| 2.4 | Задача | Хранить и показывать рекордную серию | При обнулении текущей серии сохранять максимум в «Рекорд». Показывать на экране «Прогресс». |
| 2.5 | Задача | Спроектировать логику опоздавшего приёма | Что происходит при отметке слота с опозданием: можно ли принять задним числом, пересчитывается ли остаток дня (интервал цитизина важен — не допускать два приёма подряд). |
| 2.6 | Задача | Обработать пропущенный день целиком | Если приложение не открывали день — не обнулять адхеренс молча. Предложить отметить прошлый день или закрыть массово. |
| 2.7 | Задача | Обработать ранний / двойной приём | Приём раньше слота и случай «выпил две таблетки». Учитывать для счёта остатка упаковки. |
| 2.8 | Задача | Хранить время в UTC с пересчётом в локальное | Защита от рассинхрона при смене часового пояса / перевода времени. |
| 2.9 | Задача | Определить поведение на стыке суток | Когда «Сегодняшние слоты» переключаются на новый день (полночь vs цикл сна), если последний приём поздно вечером. |
| 2.10 | Задача | Добавить состояние «курс ещё не начат» | Что показывает экран «Сегодня» до старта курса. |
| 2.11 | Задача | Определить архивацию прогресса при перезапуске курса | Старый прогресс архивируется, а не затирается. Возможность «продолжить с дня N», если забыл отмечать. |

## Эпик 3. Ощущение качественного приложения: дизайн (P2)

Передизайн из принятого демо. Внедрить целиком.

| # | Тип | Заголовок | Описание / критерии |
|---|-----|-----------|---------------------|
| 3.1 | Задача | Заменить фон на мягкий светлый, убрать чёрную подложку | Фон страницы — светлый серо-зелёный градиент. Убрать угольный фон и рваную диагональ героя. |
| 3.2 | Задача | Ввести единые тени и радиусы для карточек | Шкала радиусов 10/14/18, единая тень для всех поверхностей. Привести разнобой к системе. |
| 3.3 | Задача | Развести фоновый и акцентный зелёный | Hero-зелёный мягкий/desaturated; action-зелёный (кнопки, активный таб) насыщеннее, чтобы интерактив «выпрыгивал». |
| 3.4 | Задача | Ввести типографическую шкалу | Лейблы — мелкие uppercase + letter-spacing, серые; цифры-герои жирные; тело обычным весом. Распространить паттерн «СЛЕДУЮЩАЯ ПОЛЬЗА» на все лейблы. |
| 3.5 | Задача | Переоформить календарь курса в информативный | Пройденные дни — заливка зелёным, частичные — светло-зелёным, текущий — акцентная обводка, будущие — приглушены. |
| 3.6 | Задача | Оформить график «Таблетки по дням» | Фирменный зелёный для столбцов, минимум грид-линий (0/4/8), воздух. |
| 3.7 | Задача | Унифицировать янтарные оттенки | Один янтарь для «факт», «опоздание», «Покурил». |
| 3.8 | Задача | Усилить индикацию активного таба | Не только цвет: подложка иконки / вес. |
| 3.9 | Задача | Поднять контраст текста на карточке-герое | Текст на светлом градиенте читается слабо — поднять контраст или притемнить градиент. |
| 3.10 | Задача | Убрать дублирование мотивации на главном | Карточка «Следующая польза» и цитата говорят почти одно. Оставить одно, второе унести/чередовать. |
| 3.11 | Задача | Убрать/упростить повтор заголовка на внутренних экранах | «Свобода по дням» на каждом экране ест верх. Компактнее или убрать с внутренних. |
| 3.12 | Задача | Скрывать карточку счётчика отказа до дня 5 | До наступления вехи менять формулировку на «До отказа: N дней» либо прятать. |

## Эпик 4. Ощущение качественного приложения: тактильность (P2)

| # | Тип | Заголовок | Описание / критерии |
|---|-----|-----------|---------------------|
| 4.1 | Задача | Реализовать hold-to-confirm для «Принял» | Удержание ≈1 сек, заполнение слева направо, плавный откат при раннем отпускании, вспышка + подтверждение в конце. |
| 4.2 | Задача | Реализовать hold-to-confirm для «Покурил» | Удержание ≈1.8 сек (дольше — встроенная пауза «точно?»), контурная кнопка вместо залитой. |
| 4.3 | Задача | Внедрить iOS-хаптику через switch-трюк | Скрытый `<input type=checkbox switch>` + программный клик по label (iOS 18+). Фолбэк на `navigator.vibrate` для Android. |
| 4.4 | Техдолг | Вынести HoldButton и haptic-хелпер в переиспользуемые React-компоненты | `<HoldButton holdMs onConfirm>` + утилита `haptic()/hapticStrong()`. |
| 4.5 | Задача | Добавить мягкий перехват при «Покурил» | При срабатывании предлагать посмотреть видеопослание перед записью срыва. |
| 4.6 | Задача | Снизить визуальную доминантность кнопки «Покурил» | Контурный стиль, спокойнее залитой; деструктивное действие не должно притягивать взгляд. |

## Порядок реализации (рекомендованный)

1. **Каркас + инфраструктура:** 7.1, 1.4 (сервер+SQLite сразу, чтобы не переписывать) → 7.2–7.6.
2. **Не дать испортить данные:** 1.5, 1.1, 1.2 → 1.3, 1.6.
3. **Честная логика:** 2.1, 2.2, 2.3, 2.4 → 2.5–2.11.
4. **Ощущение:** дизайн (Эпик 3 целиком) → тактильность (Эпик 4).
5. **Завершённость:** Эпик 5.
